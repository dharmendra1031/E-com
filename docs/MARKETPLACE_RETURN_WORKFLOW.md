# Marketplace return approval workflow
Apply 10-marketplace-returns.sql after 09-customer-orders.sql. Marketplace__ReturnWorkflowEnabled defaults off; customer actions also require development checkout gate. Customer owns paid order/consumed item; requests reserve remaining return eligibility, not inventory. Existing physical receipt procedure is reused only after superadmin confirms inspected saleable stock. SQL verifies active admin role; app verifies superadmin policy. Request/review/receipt are transactional and idempotent for same request/actor. Refund, damaged stock, return window, shipping eligibility and settlement reversal are separate and not assumed. Legacy order-level ReturnRequest remains unchanged; marketplace line-level requests use a dedicated table because quantities, partial requests and review actors differ. Test data exercises paid ownership, quantity cap, non-admin rejection and duplicate physical receipt. Do not enable on real data until approved return policy, grants, browser/HTTP tests and operator training.
