# Fulfillment and payment review
Apply 08-vendor-fulfillment.sql after payment/return migrations; reapply the updated procedure before the Admin pilot. Marketplace__VendorOrdersEnabled and Marketplace__VendorFulfillmentEnabled are off by default. Approved vendor members with mapped vendor.orders ListPage/UpdatePage can mark verified paid own orders Packed then HandedOver. Admin marketplace register and detail are development-only, requiring VendorMasterEnabled and VendorOrdersEnabled; restricted admins require mapped admin.orders ListPage and UpdatePage for fulfillment changes. Admin and Vendor reuse the same list/detail/history queries, shared views and AdvanceVendorFulfillment procedure. SQL rechecks active actor role, permissions, exact vendor/order pair and verified paid status under transaction locks. A grant does not enable the old legacy order or payment mutation routes. Only authorized Admin portal actors may confirm Delivered after HandedOver, and an explicit human receipt confirmation is required. This is an operator attestation, not independently verified carrier evidence. Actor and UTC time are recorded; skipped/stale transitions and duplicate history are prevented. The parent legacy status, payment, stock and payouts are not changed by fulfillment. Vendor sees only their suborders and history (without staff actor IDs). No automatic payouts or carrier API. Existing payment review uses separate superadmin authorization and gateway verification. SQL fixtures exercise missing/revoked admin grants, wrong vendor, no delivery confirmation, vendor delivery denial and idempotent retries. HTTP/browser acceptance, actual delivery evidence process, customer delivery tracking, refund and production release remain pending.
