# Legacy customer API security (development)
Registered customer login retains its existing JSON fields and returns accessToken, tokenType, expiresIn. Send Authorization: Bearer <accessToken> on protected customer actions. No new package or table is required. The separate built-in ASP.NET Core bearer scheme uses protected tickets and does not grant Admin or Vendor access. Tickets expire after three hours; active customer/role and current credential version are checked on protected requests. Sign in again after password changes or expiry. Maintain ASP.NET Core data protection keys across deployment instances.

Protected: profile read/write, profile image, password change, address list/save/delete, orders list/detail/invoice/cancel, return request/list, product review, account deletion. Address and order records are checked against the authenticated customer. Admin notifications now require Admin; mark-seen is POST with antiforgery. SMS is Admin-only with antiforgery on writes.

Release blockers: existing native/mobile clients must adopt the bearer token; this repository does not prove their compatibility. Guest checkout, optional-user cart actions, customer password storage and reset, checkout price integrity, and legacy payment status endpoints remain separate critical security work. In particular, unauthenticated status mutations and unverified client-side payment evidence must not be exposed in production. Do not deploy this partial migration as a complete API security certification. Existing customer website cookie and Vendor portal authentication are unchanged.
