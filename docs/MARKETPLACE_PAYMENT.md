# Marketplace payment and order management foundation
Apply 06-marketplace-payment.sql after order attachment in a restored test DB. Existing Payments records remain the financial ledger; MarketplacePaymentAttempts tracks the external invoice lifecycle and uncertain send attempts. The SQL procedures are restricted internal interfaces, NOT a gateway verifier. Begin persists a single attempt before any external request; if the send response is lost, do not create another invoice automatically. Link only the verified invoice and merchant reference. Confirm only after authenticated server-to-server verification of invoice ID, exact merchant reference, paid invoice, successful transaction, currency and exact amount; the SQL procedure independently checks stored linkage, consumes reservations and posts the existing Payments record atomically. Same paid event is retryable. Never call from untrusted request data. CancelUnstartedMarketplaceOrder releases only a never-started reservation; it does not change commercial order status; release blocks a later Begin. Failed transactions on a pending invoice are not proof of terminal failure. Linked or ambiguous payments need reconciliation, and late payment after release requires manual refund/reconciliation. No gateway creation, callback or credentials used. No production enablement. Before live integration verify merchant account base currency KWD, sandbox URL, API credentials, supported invoice expiration, webhooks and marketplace supplier capabilities, payment status master IDs (existing 1/2), legacy raw SQL paths and DB execute permissions. Add unique gateway identifiers and concurrency tests in restored DB before enabling. Vendor Orders read-only flag Marketplace__VendorOrdersEnabled defaults false; queries scope to current vendor membership and verified paid attempts; no customer PII, no settlement claim, no shipping or refund actions. Commission, settlement, delivery, returns, RDLC, mobile security, browser and million-product tests remain release blockers.
