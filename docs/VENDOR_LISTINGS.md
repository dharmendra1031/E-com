# Vendor listings — phase 6A
Shared catalog is still dbo.Products. Existing VendorListings table from phase 1 is mapped in EF. Vendor owner and manager may create an offer against an active catalog product and change own SKU/price; staff can read. No new global catalog mutation by vendor. Listing queries and writes are scoped to an approved vendor and active membership; write authorization rechecked inside a serializable transaction. Existing global role is reused; detailed RolePermission integration remains pending. SKU and product uniqueness per vendor are enforced by SQL; prices are decimal(18,3). Optimistic rowversion prevents stale edits or approvals. New or changed SKU/price becomes Pending. Super admin may approve an active product for an approved vendor or deactivate a listing. No delete. Listing activation does not activate checkout or inventory. Vendor portal stays OFF by default. No production migration or legacy data backfill. SQL tests cover independent prices and stale rowversion; HTTP isolation, concurrency, decimal locale, permissions, actual production DB and browser tests remain pending. Search is SQL-side bounded paging; substring search requires workload measurement before scale claims.
